** Create a lab network

#+begin_src sh
cat > k8s-net.xml <<'EOF'
<network>
  <name>k8s</name>
  <forward mode='nat'/>
  <bridge name='virbr-k8s' stp='on' delay='0'/>
  <ip address='10.100.0.1' netmask='255.255.255.0'>
    <dhcp>
      <range start='10.100.0.100' end='10.100.0.200'/>
      <host mac='52:54:00:00:00:10' name='server' ip='10.100.0.10'/>
      <host mac='52:54:00:00:00:20' name='node-0' ip='10.100.0.20'/>
      <host mac='52:54:00:00:00:21' name='node-1' ip='10.100.0.21'/>
    </dhcp>
  </ip>
</network>
EOF

sudo virsh net-define k8s-net.xml
sudo virsh net-start k8s
sudo virsh net-autostart k8s
#+end_src

** Create VMs

#+begin_src sh
cd /var/lib/libvirt/images
sudo curl -LO https://cloud.debian.org/images/cloud/bookworm/latest/debian-12-genericcloud-amd64.qcow2

declare -A MAC=( [server]=52:54:00:00:00:10 [node-0]=52:54:00:00:00:20 [node-1]=52:54:00:00:00:21 )

for vm in server node-0 node-1; do
  # ...qemu-img create as before...
  sudo virt-install --name $vm --memory 2048 --vcpus 1 \
    --disk /var/lib/libvirt/images/$vm.qcow2 --import --osinfo debian12 \
    --network network=k8s,mac=${MAC[$vm]} \
    --graphics none --noautoconsole \
    --cloud-init root-ssh-key=$HOME/.ssh/id_ed25519.pub
done
#+end_src

** Ostree install virt

The `libvirt` package is a meta-package that pulls in the daemon and the qemu,
network, nodedev and storage drivers, so layering it is enough:

#+begin_src sh
rpm-ostree install libvirt qemu-kvm virt-install virt-manager guestfs-tools
systemctl reboot
#+end_src

*** Libvirt daemons on the lab host

The playbooks only use the `virsh` CLI on the remote host, so the libvirt
daemons must already be running there. If they are not, `virsh` fails with:

#+begin_src
error: failed to connect to the hypervisor
error: Failed to connect socket to '/var/run/libvirt/virtqemud-sock': No such file or directory
#+end_src

*** Which daemon model?

Current Fedora uses modular, socket-activated daemons (`virtqemud`,
`virtnetworkd`, ...). Older setups use the monolithic `libvirtd`. Check which
units exist:

#+begin_src sh
systemctl list-unit-files 'virt*.socket' 'libvirtd*.socket'
#+end_src

**** Check

Modular daemons:

#+begin_src sh
systemctl status virtqemud.socket virtnetworkd.socket virtstoraged.socket
#+end_src

Monolithic daemon:

#+begin_src sh
systemctl status libvirtd.socket
#+end_src

Confirm `virsh` can connect:

#+begin_src sh
sudo virsh -c qemu:///system list --all
sudo virsh -c qemu:///system net-list --all
#+end_src

**** Enable

Modular daemons (Fedora default):

#+begin_src sh
sudo systemctl enable --now virtqemud.socket virtnetworkd.socket virtstoraged.socket
#+end_src

| Socket                | Needed for                                           |
|-----------------------+------------------------------------------------------|
| `virtqemud.socket`    | Connecting to the QEMU hypervisor (`qemu:///system`) |
| `virtnetworkd.socket` | Defining and starting the lab network (`site.yml`)   |
| `virtstoraged.socket` | Storage pools and disk volumes (`virt-install`)      |

If `virt-install` later complains about node devices, also enable
`virtnodedevd.socket`.

Monolithic daemon:

#+begin_src sh
sudo systemctl enable --now libvirtd.socket
#+end_src

`enable --now` starts the sockets immediately and on every boot. The daemons
themselves start on demand when something connects.

** Troubleshooting

*** Still can't connect after enabling

check `journalctl -u virtqemud` and
  `journalctl -u virtnetworkd` for startup errors.

*** Permission denied

run `virsh` with `sudo`, or use `-c qemu:///system`. Without a URI, `virsh`
  defaults to the per-user session, which has no access to the lab network. The
  playbooks set `LIBVIRT_DEFAULT_URI=qemu:///system` for this reason.
